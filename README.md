# hackbuild-suite

Browser AI and 3D character tools in one tab: chat, voice, image, character, rooms, motion and agents, built on the hackbuild libraries.

[![licence: MIT](https://img.shields.io/badge/licence-MIT-1a1a1a)](LICENSE) [![site](https://img.shields.io/badge/site-hackbuild.github.io-fe0386)](https://hackbuild.github.io/hackbuild-suite/) [![llms.txt](https://img.shields.io/badge/llms.txt-yes-1a1a1a)](public/llms.txt)

## What it does

- Runs every model in your browser tab: chat, transcription, speech, vision, masks, depth and image models load on demand and never send your files anywhere.
- Gives you full tools, the explorers, each one screen with its subject in the middle and its settings in one rack.
- Shows one job per example, each a single TypeScript file you can read on screen, copy and run.
- Opens from a web host, or as one HTML file from your disk.

## Use it

Open <https://hackbuild.github.io/hackbuild-suite/>. The home page opens on the dog simulator's yard; the explorers and the examples sit under it. `/` or ctrl+k opens the switcher. The model chip in the bar opens the model sheet for the tool in front of you: pick a model, see its size and licence, and load it.

To use it offline, download `files/hackbuild-suite.html` from the same site, or one file per group (`files/chat.html`, `files/voice.html`, `files/image.html`, `files/character.html`, `files/rooms.html`, `files/motion.html`, `files/agents.html`), and open it from disk.

## Examples

Each example does one job in one file, `examples/<job>/<id>/example.ts`, listed in [examples/index.json](examples/index.json). It imports published packages only (@hackbuild/\*, @virgilvox/hackbuild-ui, three, vue), exports `mount(host, hooks?)`, draws a hackbuild-ui layout and binds a view package to a library. On the site each example shows its live result first, then its source, its install line and its readme.

| job | examples |
|---|---|
| talk | chat with a small model, a reply with its thinking folded, answer as json to a schema, remember facts across chats, a character card in and out |
| listen | transcribe a file, push to talk dictation, speak a line, speak with lip sync |
| see | find objects on the webcam, cut out a subject with a click, depth from a photo, ask about a picture |
| make | text to image, photo to relief |
| move | load a vrm, glb or fbx and pose it, retarget a clip, reach with two bone ik, a dog that walks |
| think | a creature with drives, a camera that follows |

Every model loads for real: `jobLoader(job)` from @hackbuild/ai-views fetches the runtime and the weights when you press load. Until then an example shows a written sample labelled "sample, no model loaded". The sample photos in `examples/samples` are CC0; [examples/samples/CREDITS.md](examples/samples/CREDITS.md) names their sources.

## Privacy

- Your photos, recordings, chats and designs stay in this tab. Projects live in your browser's IndexedDB; nothing is uploaded.
- Model weights download from their hosts (Hugging Face and the runtime CDNs) only when you press load, and are kept in browser storage for next time. The model sheet shows what is stored and lets you remove it.
- API keys you enter for remote models stay in this browser and go only to the host you named.
- No analytics and no tracking.

## Browser support

| feature | needs | without it |
|---|---|---|
| chat, image and depth models | WebGPU (Chrome and Edge on desktop; Safari and phones where the browser turns it on) | smaller models on WASM, slower; the model sheet says which fit |
| threaded WASM runtimes | cross origin isolation, set by the site's service worker | one thread |
| camera and microphone | a secure origin and your permission | files only |
| the single file build | any current browser from `file://` | some runtimes that need a worker from a URL stay off |

Phones get the same tools with the rack as a bottom sheet; large models may not fit in a phone's memory, and the model sheet marks them.

## Works with

The suite only consumes these; every reusable piece lives in them.

- [hackbuild-browser-ai](https://github.com/hackbuild/hackbuild-browser-ai): chat, speech, vision, depth and image models and the model catalogue. [llms.txt](https://hackbuild.github.io/hackbuild-browser-ai/llms.txt)
- [hackbuild-motion](https://github.com/hackbuild/hackbuild-motion): avatars, retargeting, ik, gait and lip sync on three.js. [llms.txt](https://hackbuild.github.io/hackbuild-motion/llms.txt)
- [hackbuild-agents](https://github.com/hackbuild/hackbuild-agents): drives, senses, cameras and movers for agents in a scene. [llms.txt](https://hackbuild.github.io/hackbuild-agents/llms.txt)
- [hackbuild-ui](https://github.com/hackbuild/hackbuild-ui): the design system, its six layouts and the model picker. [llms.txt](https://hackbuild.github.io/hackbuild-ui/llms.txt)
- [dog-simulator](https://hackbuild.github.io/dog-simulator/): the yard on the home page.

For agents and LLMs, [public/llms.txt](public/llms.txt) (served at the site root) lists every explorer and example with its source path. To build on the suite, or add an explorer or an example, read [docs/BUILDING.md](docs/BUILDING.md).

## What is verified

### Not verified by anything

- any example or explorer with a real model: the real loaders are in place, and every gate runs them on stand ins behind `?stub`.
- the yard on home is a still taken headless from the live dog simulator; its press plays the live site in a frame, which no gate has loaded.

### Verified

- the single file build opens from file:// in headless system Chrome, changes route and writes and reads IndexedDB (`tools/smoke-file.mjs`).
- home: no modal, one bar, the yard and one pink action in the first view, every explorer, every example by job (`tools/smoke-home.mjs`).
- each job's examples: the layout, the sample, and the source on screen equal to the file (`tools/smoke-examples.mjs <job>`).
- each rebuilt explorer on `?stub` (`tools/smoke-x-<name>.mjs`).
- home, every example and every explorer pass the screen gate at desktop and phone widths (`tools/ux-gate.mjs`).
