# hackbuild-suite

Browser AI and 3D character tools in one tab: chat, voice, image, character, rooms, motion and agents, built on the hackbuild libraries.

Use it: <https://hackbuild.github.io/hackbuild-suite/>. Single files to
download and open from disk: `files/hackbuild-suite.html` and one file per
group (`files/chat.html`, `files/voice.html`, `files/image.html`,
`files/character.html`, `files/rooms.html`, `files/motion.html`,
`files/agents.html`) on the same site.

Status, 2026-11-25: one bar, a home that opens on the dog simulator's yard,
eight explorers that open today's tool pages until each is rebuilt, the
examples below, and the single package benches under parts. Examples run on
stub loaders; nothing real has been downloaded or run in the gates.

## The shell

One light bar: the mark; the tool name, which opens the switcher (explorers,
then the examples by job, then parts); one model chip for the current tool,
which opens the model sheet; and a menu with the project, settings, keys and
the log. `/` or ctrl+k also opens the switcher.

## Examples

Each example does one job in one file, `examples/<job>/<id>/example.ts`,
listed in `examples/index.json`. It exports `mount(host)`, draws a
hackbuild-ui layout and binds a view package to a library; it returns its
model pick (shown as the bar chip), a `sample` that runs its built in sample,
and `dispose`. On the site each example shows its live result first, with a
foot that holds the source toggle (the file itself, read raw at build time,
with a copy button), the install line and the package readme on npm.
`examples/shared/fixtures.ts` holds the stand ins the examples share: the
stub loader, a machine fixture and drawn samples. Swap `stubLoader` for
`weightsLoader(store)` from @hackbuild/ai-views, or a runtime's loader, to
load real weights.

| job | examples |
|---|---|
| talk | chat with a small model, a reply with its thinking folded, answer as json to a schema, remember facts across chats, a character card in and out |
| listen | transcribe a file, push to talk dictation, speak a line, speak with lip sync |
| see | find objects on the webcam, cut out a subject with a click, depth from a photo, ask about a picture |
| make | text to image, photo to relief |
| move | load a vrm, glb or fbx and pose it, retarget a clip, reach with two bone ik, a dog that walks |
| think | a creature with drives, a camera that follows |

To add one: write `examples/<job>/<id>/example.ts`, add its row to
`examples/index.json` and its route to `tools/ux-routes.json`, then run
`node tools/llms.mjs`, `npm run smoke:examples <job>` and the screen gate.
The library repos copy the same files into their examples folders.

`llms.txt` at the site root (generated by `tools/llms.mjs`) lists every
example with its source path, and links the four libraries' llms.txt.

Built on:

- hackbuild-browser-ai, <https://github.com/hackbuild/hackbuild-browser-ai>, pages <https://hackbuild.github.io/hackbuild-browser-ai/>
- hackbuild-motion, <https://github.com/hackbuild/hackbuild-motion>, pages <https://hackbuild.github.io/hackbuild-motion/>
- hackbuild-agents, <https://github.com/hackbuild/hackbuild-agents>, pages <https://hackbuild.github.io/hackbuild-agents/>
- hackbuild-ui, <https://github.com/hackbuild/hackbuild-ui>, pages <https://hackbuild.github.io/hackbuild-ui/>
- dog-simulator, <https://hackbuild.github.io/dog-simulator/>

The libraries and hackbuild-ui are vendored as tarballs pinned by commit
under `tools/vendor/`.

Two builds: `npm run build` for any http host (lazy chunks per tool), and
`npm run build:single` for one HTML file that also opens from `file://`.
`npm run smoke:file` opens that file in headless Chrome and checks the
routes and the IndexedDB workspace.

## Develop

    source ~/.nvm/nvm.sh && nvm use
    npm ci
    npm test

`npm ci` sets `core.hooksPath` to `.githooks`. Rules for every change are
in RULES.md and CONTRIBUTING.md.

## What is verified, and what is not

### Not verified by anything

- any example or tool with a real model: every gate runs on stub loaders.
- the yard on home is a still taken headless from the live dog simulator on 2026-11-25; it does not move yet.

### Verified

- the single file build opens from file:// in headless system Chrome (puppeteer-core 25.18.1), changes route and writes and reads IndexedDB (`tools/smoke-file.mjs`).
- home: no modal, one 52 px bar, the yard and one pink action in the first view, eight explorers, every example by job, the switcher in order (`tools/smoke-home.mjs`).
- each job's examples: the layout, the sample, and the source on screen equal to the file (`tools/smoke-examples.mjs <job>`).
- home and every example pass the screen gate at 1440 and 390 (`tools/ux-gate.mjs`).
